# xinxishouji

`xinxishouji` 是一个面向多平台资讯/线索自动化收集的项目蓝图，目标是把闲鱼、小红书、X（Twitter）和 Reddit 上的公开信息，按照关键词、账号、社区、商品类目等规则进行采集、清洗、去重、分析和通知。

> 重要原则：项目只应采集你有权访问、平台规则允许、且符合当地法律法规的数据；优先使用官方 API、开放数据源或平台授权能力，不绕过登录、验证码、风控、隐私设置或付费墙。

## 核心目标

- **多平台采集**：支持闲鱼、小红书、X、Reddit 等来源，并预留更多平台接入能力。
- **统一数据模型**：把不同平台的帖子、商品、评论、作者、互动数据统一成可查询的标准结构。
- **自动化监控**：按关键词、话题、作者、社区、价格区间等条件定时抓取和增量更新。
- **质量控制**：对重复内容、低价值内容、广告、异常账号和无关信息进行过滤。
- **分析与通知**：支持趋势分析、情绪/意图识别、线索评分、日报/周报和即时告警。
- **合规优先**：每个平台接入前先确认数据来源、授权方式、频率限制和存储边界。

## 当前阶段

当前仓库处于**产品与技术方案设计阶段**。下一步建议先确认你的使用场景，例如：

- 想监控哪些关键词、品牌、商品或话题？
- 采集结果主要用于商机发现、舆情监测、选品分析，还是内容创作选题？
- 是否需要实时告警，还是每天/每周汇总即可？
- 团队是否已经拥有 X、Reddit 或其他平台的官方 API 权限？

确认这些问题后，可以进入 MVP 开发：先选 1 个合规且稳定的数据源，打通“采集 → 入库 → 搜索 → 通知”的最小闭环。

## 在线网页

本仓库已添加 GitHub Pages 静态采集工作台原型 `index.html`。仓库 Pages 发布源选择 `main` 分支的 `/(root)` 后，可通过以下地址访问：

<https://final668.github.io/xinxishouji/>

当前网页支持在浏览器本地配置多平台采集规则、合规确认、模拟运行日志，以及导出后端调度器可读取的 JSON 任务配置。GitHub Pages 只能运行静态前端页面，真正自动化采集需要另外部署后端服务，并优先接入官方 API、授权数据源、RSS、人工上传或平台允许的公开分享内容。

如果页面暂时无法打开，请等待 GitHub Pages 部署完成，或在仓库的 **Settings → Pages** 页面查看最新部署状态。
